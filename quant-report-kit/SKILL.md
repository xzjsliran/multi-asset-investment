# 投资回测研究报告

全部资产只做多。接收回测时检查证券/大类/动态权重、已提供持仓和目标权重均非负，现金不透支；出现负持仓时先修复输入，不能继续生成只做多报告。负收益、回撤和卖出金额可以为负。外部输入只有净值时，明确“无法验证持仓方向”，不补造已核实声明。

收到`quant-rebalance-kit`的`handoff.json`且`document_type=rebalance_plan`时，使用`rebalance --plan <调仓结果目录> --out <新报告目录>`，模板为[组合调仓计划](assets/rebalance-report-template.json)。先确认live计划已有用户确认记录；demo保留历史模拟标识。报告列示当前、目标和预计调整后的差异，不能把计划数量写成实际成交或未来收益预测。用`check --report-dir <报告目录>`复核。

默认读者是商业客户。采用专业投资研究表达；开发教学仅在用户明确要求开发指导时使用单独指南。内部目录、预设ID及讨论代称只用于定位输入，不能作为客户显示名称。

## 先读取报告契约

- [投资回测报告规范](references/投资回测报告规范.md)：表达逻辑、比较方法、披露及复核要求。
- [结构化模板](assets/investment-report-template.json)：章节ID、标题、数据来源和必要说明；HTML与文字报告共用。
- [正文模板](templates/投资回测报告模板.md)：写作骨架。
- [配置Schema](assets/report-config.schema.json)与[解读Schema](assets/commentary.schema.json)：其他agent组装请求及解读的字段约定。

## 定位输入与确定名称

沿用当前任务已有的结果、年份和客户要求。已有明确输入直接执行；目录不明时在指定项目查找`handoff.json`。检查实际可用的场景、币种、历史范围及明细。

一份结果默认包含实际导出的等权、固定权重和基准对照；`--main-only`仅分析主策略。多份结果使用独立id、专业label和结果目录。名称应描述资产范围或规则，如“多资产配置策略（QDII权益）”“VIX动态资产配置策略”。不要在名称里承诺低风险或稳定收益。

资产组合需要改显示名时，在对应策略配置中提供`display.sleeves`（资产组合ID到名称的映射）；状态名称通过`display.states`映射。原输入文件保持不变。程序识别少数既有历史名称，其他不合适的名称由agent根据实际配置改写，不能凭名字猜测策略。

默认共同区间比较：同币种、同估值日期；不插值补净值。外部净值先用`import-nav`接入，核实资金流处理及币种。只有净值时仅分析绩效风险，不补造持仓、选股或交易信息。

## 生成并核对

1. 复用本项目Python环境，必要时安装`requirements.txt`。输出放到kit及输入目录以外的新目录。
2. `scripts/run.py inspect --result <结果目录>`检查可用场景。
3. 单结果使用`single --result <目录> --name <专业名称> --out <新目录>`；多策略使用`build --config <配置.json> --out <新目录>`。命令前使用实际Python路径。
4. 读取`checks.json`、`comparison.csv`、`ai_context.json`，核对共同区间、基准、成本和数据限制。
5. 需要补充研究分析时，根据本次事实生成解读JSON。每段包括`section`（summary/comparison/portfolio）、`title`、`text`、`evidence_ids`；标题使用研究主题或支持得出的结论。每个数字、方向、比较条件及推断逐项对照输入，不能只附事实编号。
6. 使用相同报告配置及`--commentary <解读.json>`写入新版本。执行`check --report-dir <报告目录>`，再实际打开HTML，检查曲线、名称、切换后的明细和披露。
7. 向用户交付报告及必要结论。保留复核资料，不把文件指纹、原目录路径和代码字段堆入客户正文。

完整命令见[使用指南](references/使用指南.md)。其他能读取文件并运行Python的宿主采用相同调用方式，无须MCP或额外模型API。

## 研究判断

研究摘要应概括风险收益特征及比较含义；主体依次提供策略设定、绩效、差异、贡献和局限。各章节增加信息，不重复摘要数字。对比不限于既有配置或固定策略数量。

横向比较同时发生资产、权重或选股变化时，讨论整体方案差异。程序仅把同一回测、相同价格指纹的主策略与配套static/equal_weight场景标为受控对照。相同价格指纹本身不足以确认其他条件相同。市场基准与多资产组合风险暴露不同，不能把原始收益差直接写成alpha。

资产组合盈亏分解写“收益贡献”，不能写成宏观因果归因。VIX阈值只代表所设条件，不能直接宣布经济周期转折。历史期末持仓带日期，不写成当前调仓建议。缺少样本外检验时不得声称稳健性已经验证。

报告包含实际回测的风险贡献：用各部分逐日盈亏/上一日组合权益计算，与组合日收益的协方差分解年化波动；贡献合计等于年化波动率，占比合计为100%。共同区间重算。负风险贡献可来自分散作用，不表示空头；零波动时占比不定义。读取`risk_contributions.csv`、`risk_correlations.csv`及`ai_context.json`的`risk`。相关性是收益贡献序列，包含仓位变化，不能称为纯资产价格相关性。

风险平价的`regimes.json`另有代理协方差下的目标风险贡献，与实际回测波动贡献分开解释。调仓报告展示“目标配置风险估计”，不能将其称为实际执行后的风险分布。缺少分部分盈亏时不补造风险贡献。

## 机构信息与检查边界

`report`可填实际报告日期、版本、编号、出具机构、研究人员、复核人员、分发范围及利益冲突说明。未知字段省略，不填写虚构信息或默认“无利益冲突”。

当前产物是投资策略历史回测研究。正式证券研究报告及基金宣传推介材料应由实际出具方依据自身资质、服务性质和分发渠道补充适用内容；参见[监管依据与适用范围](references/监管依据与适用范围.md)。`publication_checks.json`分别记录计算/格式检查、未提供的机构信息和待人工核实内容。程序不签发法律合规认证，不自动发送或发布报告。

最终套装仅保留代码、空模板、Schema、Skill、文档和人工测试数据；市场数据、客户结果、凭证与报告输出留在使用者工作目录。
