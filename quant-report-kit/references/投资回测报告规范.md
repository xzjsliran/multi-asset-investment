# 投资回测报告规范

版本2.1，2026-10-07。适用对象为商业客户；本文件同时作为生成报告的agent写作规则和人工复核依据。

## 1. 报告的研究任务

报告评价既定投资规则在指定历史区间内的收益、风险和配置特征。读者应能判断方案之间的差异、承担的风险及结果成立的条件。研究摘要给出结论，正文展开依据，附录保存口径。

标题使用“资产配置策略对比”“VIX动态配置策略回测分析”等专业主题。章节使用“累计净值走势”“回撤走势”“QDII权益替代的绩效影响”等名称。标题不统计策略数量，不向读者提问，不使用读图指令。

内部讨论名称和开发阶段名称不进入客户输出。策略以资产范围及规则命名；显示名称不能暗示未经检验的安全性或收益稳定性。文件路径、内部ID和原始字段仍保留在机器复核资料，保障复现。

## 2. 固定结构与证据

| 章节 | 需要回答的研究内容 | 数据依据 |
|---|---|---|
| 研究摘要 | 风险收益特征、主要方案差异及其解释边界 | 本次指标、受控对照及已提供的决策记录 |
| 策略概况与回测设定 | 资产范围、基础比例、选择及配权、调仓、条件规则、区间、币种、成本和基准 | 实际配置、交接清单、数据及执行说明 |
| 绩效与风险分析 | 累计/年化收益、波动、回撤、夏普、年度与月度分布 | 同一区间重新计算的净值和指标 |
| 策略比较分析 | 绩效差异、同时改变的配置、受控对照结论 | 指标差值、配置差异、输入指纹及对照类型 |
| 资产配置与收益贡献 | 各资产组合的贡献、权重变化、期末持仓和关键调仓记录 | 该策略自己的盈亏、持仓及决策文件 |
| 研究局限与风险提示 | 历史模拟性质、成本影响、样本覆盖、历史数据修订、成交近似及适用范围 | 本次真实假设和未覆盖事项 |
| 附录：指标定义与完整区间 | 指标口径、完整区间结果、资料来源 | 计算方法及原始记录 |

单策略不展示不存在的比较。只有净值时保留绩效分析，持仓及贡献注明输入未提供。不得用主策略的持仓解释等权、固定配置或基准场景。

## 3. 摘要和结论的写法

每个判断包含对象、区间、证据和含义。先交代风险收益特征，再解释与参照方案的差异；必要时说明比较边界。摘要通常2—4段，信息量决定段数，不机械凑数。

例如，同一回测导出的动态与固定权重对照，可以写：“在相同价格输入和调仓日历下，动态权重方案的累计收益高于固定权重方案，最大回撤较浅。该差异反映所设权重规则在本区间的模拟影响。”实际使用时填写本次计算数字，不能照抄其他回测数值。

横向方案中若同时改变资产和选股，则说明整体差异，不把改善归因于VIX或某个配权方法。只写“表现更好”没有比较对象、指标和样本范围，不构成完整研究结论。指标差异使用百分点；相对比例变化另行计算并注明分母。

标题、摘要、图表和解读不逐段重复同一组收益率。图表标题注明统计对象；说明文字仅补充基点、单位或必要口径。原始字段对照放在复核资料，客户正文使用中文配置项。

## 4. 关键披露

所有资产采用只做多约束，基础、动态和证券权重均非负，现金不透支。报告输入中的负持仓应返回修复；卖出金额、负收益与回撤不属于空头持仓。仅提供净值的外部结果注明无法验证持仓方向，不视作已核实的只做多持仓记录。

报告首页标明历史模拟性质、回测区间、计价币种、报告日期和版本。机构及署名信息仅使用实际提供内容。数据截至日与报告制作日分开。

交易成本为0时明确列示，不描述为费后收益。调仓成交、分数份额、复权、现金收益、跨市场报价对齐等沿用原回测说明。财务及宏观数据的可用时点和历史修订限制需要保留，不能仅凭信号检查无误就宣称完全消除了未来信息。

参照基准写明证券及规则；单一权益基准和多资产策略的风险暴露差异需要说明。年化收益基于不足一年的区间时仍披露实际日期，不能扩大成年年可实现的回报。

没有独立样本外、滚动前推或参数敏感性结果，就说明未提供这些检验，不使用“长期有效”“稳健性已验证”等结论。历史持仓注明截面日期；最新调仓建议由后续模块基于最新数据和客户约束另行计算。

## 5. Agent调用和复核

`assets/investment-report-template.json`是章节及标题契约，HTML和Markdown据此生成。`report-config.schema.json`定义请求；`commentary.schema.json`定义解读。报告内容结构为2.1版，回测交接及请求的`schema_version`继续使用1。

agent先生成数据报告，再读取本次`ai_context.json`。解读引用该次facts；更换配置、年份、策略顺序后重新读取编号。若需要fact之外的新事实，先扩展计算并导出证据，不引用一个无关编号支持自己的推测。

运行检查覆盖净值、日期、币种、贡献加总、内部名称、标题规则、收益保证关键词、必要披露和事实引用。它不判断整段自然语言是否逻辑正确，也不能核实出具机构资质、利益冲突或发布审核。agent须逐句复核数字和含义；机构信息缺项记录在`publication_checks.json`。

正式使用的要求随报告性质和出具方确定，见[监管依据与适用范围](监管依据与适用范围.md)。
