# 项目维护与发布

仓库维护统一入口、四个投资模块和四个平台适配层。VERSION 为当前发行版本，Release 保存对应安装包。

## 源码与用户资料

计算代码在各 kit 维护，宿主差异集中在 adapters/codex、adapters/claude-code、adapters/workbuddy、adapters/dsh。各 kit 的 references 仅保留投资使用所需说明；本地资料和运行结果由 .gitignore 排除。

修改模块时保留输入输出约定；投资用户的数据、账户、凭证和运行环境不进入源码或安装包。报告模板 assets/report-template.html 已预编译，正常生成报告无需 Node.js。

## 构建版本

先更新 VERSION 和四份安装指南并提交源码。随后从该提交生成四个平台安装包：

```bash
python scripts/build_codex_release.py --out output/releases/v0.3.0/codex
python scripts/build_claude_code_release.py --core-ref HEAD --out output/releases/v0.3.0/claude-code
python scripts/build_workbuddy_release.py --core-ref HEAD --out output/releases/v0.3.0/workbuddy
python scripts/build_dsh_release.py --core-ref HEAD --out output/releases/v0.3.0/dsh
```

输出目录必须是新目录。四个包共用已提交的核心源码，平台脚本仅叠加宿主入口、清单和运行约定。通用构建脚本按投资资料清单收集 references，不收集本地归档和测试目录。

为源码提交创建版本标签并推送，将四份 ZIP 和对应 SHA-256 清单上传到同一 Release。Release 标题只使用版本号，正文写功能变化、下载文件和安装方法，不写验证情况。当前 0.3.0 的更新说明为“统一了策略配置、文件及命令的专业命名”。

仓库和 Release 均为公开。适配安装方法见各平台 INSTALL.md；运行记录保存在维护者本地。

配置名称、预设标识和文件名按资产范围或策略规则统一命名。共享打包程序会检查分发路径以及JSON中的名称、标题和标签，发现内部代称时停止生成安装包。
