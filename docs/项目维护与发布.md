# 项目维护与发布

仓库维护一份核心源码，Release 保存各平台可安装的产物。当前版本号见根目录 `VERSION`；Codex 包内的版本由构建脚本从该文件生成；Claude Code 追加包从指定核心提交的 VERSION 读取版本。

## 日常改动

在现有主工作目录中修改对应 kit；有多项并行工作时使用短期功能分支。四个 kit 的接口与样例随代码一起维护。平台入口、清单和运行约定放在 `adapters/<平台>/`，避免复制后再分别修改计算代码。

改动完成后运行相关测试；涉及模块交接或发版时运行全部测试。测试使用人工样本，GitHub Actions 不配置数据密钥、不调用 iFinD 或真实行情接口。

本机验证（临时文件保存在既定位置）：

```bash
mkdir -p /Users/ranli/Documents/Codex/temp/multi-asset-tests
export TMPDIR=/Users/ranli/Documents/Codex/temp/multi-asset-tests
export QUANT_REPORT_TEST_TMP="$TMPDIR"
python -m unittest discover -s quant-data-kit/tests -q
python -m unittest discover -s quant-strategy-kit/tests -q
python -m unittest discover -s quant-report-kit/tests -q
python -m unittest discover -s quant-rebalance-kit/tests -q
python -m unittest discover -s tests -q
```

其他电脑使用自己的临时目录。提交前检查文件列表，确保只有代码、配置样例、模板和文档。根目录 `.gitignore` 排除本地 `output/`、`资料/`、根目录 `references/`、研究材料、环境、行情文件和凭证；各 kit 内的 `references/` 是使用说明，会进入仓库。

方案与申报文件集中在 `资料/`，每轮运行结果完整放在 `output/验证与测试/<批次>/`。当前可看的报告由该目录的 README 提供入口；旧交付快照放在 `output/历史交付/`。历史报告内的来源路径记录生成时的位置，迁移后的对应位置见本地整理记录。

## Codex 发版

1. 更新 `VERSION`，完成测试并提交源码。后续同一版本的安装包应对应同一提交；有修订则使用新版本号。
2. 试构建先放到 `/Users/ranli/Documents/Codex/temp` 下的任务目录。正式构建从干净的源码工作区生成，输出使用新版本目录：

   ```bash
   python scripts/build_codex_release.py --out output/releases/v0.1.0
   ```

3. 将生成的 ZIP 解压到另一个目录，检查 `startup`、策略配置及数据计划，并在 Codex 插件目录验证识别。首次启用使用人工样本，不必消耗真实数据额度。
4. 为通过验证的提交建立 `v0.1.0` 标签并推送，创建同名 Release，上传 `multi-asset-investment-codex-v0.1.0.zip` 和 `SHA256SUMS`。发布说明写明新增内容、下载文件和安装入口。
5. 未来 WorkBuddy 或其他宿主的安装包可以追加到对应核心版本的 Release；若核心也改动，整体发布新版本。适配源码始终进入仓库。

GitHub 自动生成的 Source code 下载项保留源码结构；提供给 Codex 用户的文件是命名中带 `codex` 的 ZIP。Release 不打包真实研究结果。

## Claude Code 追加发行

适配层在 `adapters/claude-code/`，复用核心标签的四个模块和统一 Skill。先提交适配源码，再运行：

```bash
python scripts/build_claude_code_release.py --core-ref v0.1.0 --out output/releases/v0.1.0/claude-code
```

将生成的 `multi-asset-investment-claude-code-v0.1.0.zip`和 `SHA256SUMS-claude-code.txt` 追加到已有 v0.1.0 Release。保留原 Codex 附件、校验文件与标签；包内分别记录核心提交和适配层提交。

2026-10-08 首次 Claude Code 适配按维护者明确要求直接发布试用，未运行自动测试、插件校验、安装或端到端验证。本次推送用 `[skip ci]` 提交标记跳过自动测试，构建记录保留在本地。该安排只针对本次发行。

## 发布范围

仓库初始为私有，Release 附件遵循仓库访问范围。将来开放给外部用户时，再确定仓库可见性、发行授权与第三方组件说明。报告的前端模板维护依赖详见 `quant-report-kit/references/维护与验证.md`；使用预编译模板不需要 Node.js。

## 发布说明约定

Release 面向内部使用，仅说明功能变化、对应平台下载文件及安装方法。按维护者要求，今后不在发布说明中撰写验证情况；实际运行与验证记录保留在维护资料中。
