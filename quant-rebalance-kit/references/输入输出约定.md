# 输入输出约定

## 文件与计算入口

`scripts/run.py`提供`import-account`、`review`、`quotes`、`plan`及`simulation`。Python可调用`rebalancekit.planning.make_plan(config, data, account, request, quotes, confirmation)`。`data`为同级策略kit的`Dataset`。策略内核统一调用`strategykit.decision.decide`。

结构定义见`assets/account.schema.json`、`request.schema.json`、`quotes.schema.json`、`confirmation.schema.json`。Schema描述格式，代码还验证时点、数量关系、现金和权重加总。

## 账户

账户`source=actual`用于实际账户，`simulation`用于历史模拟。`as_of`使用带时区的时间。每条持仓以`(sleeve, code)`唯一，数量和可卖数量非负，可卖数量不超过数量。同一证券可以属于多个部分；由用户明确归属，在账户层合并交易净额。

现金按`(sleeve, currency)`唯一、以原币计价。`cash`部分表示未分配现金。股票内部调仓只用股票部分原有资金及卖出回款；大类调仓共享本次参与部分的资金，仍按币种分别核算。新增现金先更新账户快照；现金变化后重新确认。

`strategy_state`可保存：

| 字段 | 含义 |
|---|---|
| `strategy_digest` | 产生该状态的策略摘要；策略改变时需要确认如何重新配置 |
| `previous_allocation` | 上次确定的大类配置。宏观缺指标时选择hold且已有持仓时必填 |
| `inner_weights` | 各部分上次内部目标权重；缺省可从已确认的当前持仓推得漂移比例 |
| `last_allocation_execution` | 已实际执行的大类调仓日期 |
| `last_execution_by_sleeve` | 各部分已实际执行的调仓日期 |

已执行日期不能晚于账户快照。计划生成后不更新这些实际执行字段；用户成交后再核实。存在未完成委托时，先核对其占用现金和可卖数量，当前组件不模拟挂单成交。

## 计划请求与时间

- `mode`：live须有实际账户和用户确认；simulation可以使用模拟账户。
- `as_of`：本次信息截止时间，带时区。
- `execution_date`：可选。指定日期时取该日或其后的第一个已核实交易日并判断是否到期；不指定时寻找下一次到期事件。指定非调仓日可能输出维持持仓。
- `initial_allocation`：初始建仓或明确要求重新配置时为true，会在选定执行日更新全部部分。不能为方便而给已有账户自动设true。
- `max_quote_age_days`：原始报价及汇率有效期，缺省7天；证券旧价可带提示估值，不能用于买卖数量。
- `max_signal_gap_sessions`：入选证券研究行情允许缺失的交易日数，缺省5。
- `minimum_trade_value_cny`：忽略较小调整的金额门槛，缺省0。
- `cash_buffer_cny`：额外最低现金金额，缺省0；不足时列示约束，不能融资满足。

策略沿用中国交易日16时的信息截点，通常期末形成信号、下期首个交易日执行。未到信号日时只使用已完成交易日的数据，保留计划信号日并标记预案。实际成交时间和成交价格在成交后记录，不能从参考报价推断。

## 报价

研究信号使用复权序列；数量计算只接受`price_basis=raw`的原币价格。每个报价含`code/price/currency/available_at/source/buy_lot/sell_lot/tradable`，且时间不晚于as_of。`fx`按币种列`rate_to_cny/available_at`；CNY隐含汇率为1，其他币种必须提供。境内QDII使用自身人民币场内原始价。

`quotes`命令可以从数据kit的标准表提取`close_raw`；美国证券使用`close_usd`和已知`usd_cny`。输入`instrument-rules`列明交易单位和币种。外币证券在live模式还须有`execution_session`，表明已经核实拟执行日为当地可交易日；未核实则暂不产生该证券的交易数量。

不自动换汇。某币种资金不足时按比例缩减该币种买入，保留资金缺口；资金到位后更新账户并重新测算。实际产品的零股处置、可卖规则或冻结情况可通过交易单位及可卖数量表达；首版未连接券商订单系统。

## 输出

| 文件 | 作用 |
|---|---|
| `plan.json` | 完整计划，包括确认状态、日期、事件、目标、买卖、约束、宏观证据、优化记录与后续日历 |
| `targets.csv` | 各部分目标金额和权重；现金代码为`__cash__` |
| `holdings.csv` | 当前数量、预计调整后数量、当前/目标/预计权重及金额偏差 |
| `orders.csv` | 按证券合并后的净买卖；quantity非负，side区分买卖，signed_quantity可因减持为负 |
| `allocation_legs.csv` | 各部分内部调整记录；可能相互抵消，不应逐条直接下单 |
| `cash_after.csv` | 预计调整后各部分、各币种现金 |
| `strategy.json` | 本次策略版本 |
| `checks.json` | 只做多、资金守恒、权重加总等计算核对 |
| `ai_context.json` | 报告及宿主解读的证据路径 |
| `handoff.json` | 文件清单、摘要、字段单位和报告路由 |

JSON不使用NaN或Infinity；CSV为UTF-8 BOM，即使没有交易也保留表头。金额统一到CNY进行配置，订单同时保留原币金额。输出不得写入kit目录或覆盖已有非空结果目录。

`state_if_fully_executed`只是预期状态。它既不是账户快照，也不是成交回执。实际账户下次计算仍需提供真实持仓；对只执行了一部分的情况重新测算差额。

## 报告衔接

`document_type=rebalance_plan`交给报告kit的`rebalance`命令，报告使用`assets/rebalance-report-template.json`。报告分开列目标比例与受约束后的预计比例，明确模拟性质、数据时点、原始参考报价、预计数量、成本及只做多要求。未来月份的预案不得写成已知月底结果。
