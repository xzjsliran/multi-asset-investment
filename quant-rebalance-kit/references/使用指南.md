# 组合管理与调仓计划使用指南

本指南用于运行成品、复核输入和查看输出。从头开发本模块的过程见[WorkBuddy开发指南](WorkBuddy开发指南.md)。

## 在WorkBuddy中开始

将`quant-data-kit`、`quant-strategy-kit`、`quant-report-kit`、`quant-rebalance-kit`放在同一目录，让宿主读取相应的SKILL.md。沿用已安装的数据/策略Python环境即可；新环境运行`python -m pip install -r quant-rebalance-kit/requirements.txt`。Tushare仍只通过本地代码读取个人环境中的凭证。

实际使用可以这样说：

> 请使用这个项目的组合调仓组件。先查看我的策略文件和持仓表，向我汇总本次策略、资产部分归属、持仓数量、可卖数量、各币种现金及时间，待我确认后再计算下一次调仓。全部资产只做多。请按最新可用数据列出目标比例、买卖数量及未能满足目标的原因，并调用报告模块生成组合调仓计划。

用户确认时应能看到持仓表，而不只是一个文件名。账户存在未完成委托时先核对其状态。对原有仓位所属的资产部分有疑问，先明确归属；这决定股票周度调仓能动用哪些资金。

需要先看演示可以这样说：

> 使用已有的多资产配置策略（QDII权益）及本地历史数据，模拟2025年6月30日收盘后的账户，计算下一次调仓并形成报告。核对它和历史回测的目标权重。标明历史模拟日期；不需要我的实际持仓。

## 文件准备

策略文件沿用策略kit配置。账户可从券商导出表整理为JSON，或准备两份CSV再转换：

- 持仓表列：`sleeve,code,quantity,available_quantity`，分别为资产部分ID、代码、持有数量、可卖数量。
- 现金表列：`sleeve,currency,amount`，分别为现金归属、币种、可用金额；未分配现金的sleeve填`cash`。
- 数量使用实际份额；不把回测的复权记账单位直接当作券商份额。现金使用原币金额。

`assets/account.template.json`与`request.template.json`是待填模板，空时间和空账户须补全。代码保持字符串，避免丢失前导零。可卖数量不明时询问用户，不能默认全部可卖。

下列命令使用项目当前目录；其他机器替换`ROOT`和`WORK`，始终使用同一Python环境。正式客户账户和输出选择自己的本地工作目录；临时CSV等文件放在`/Users/ranli/Documents/Codex/temp`的任务子目录。

```bash
ROOT='/Users/ranli/github/multi-assets/量化教学'
PY="$ROOT/.venv-data/bin/python"
WORK='/Users/ranli/Documents/Codex/temp/quant-rebalance-manual'
mkdir -p "$WORK"

"$PY" "$ROOT/quant-rebalance-kit/scripts/run.py" import-account \
  --positions-csv "$WORK/positions.csv" --cash-csv "$WORK/cash.csv" \
  --as-of '2025-06-30T16:00:00+08:00' --out "$WORK/account.json"
```

上面的日期只是文件格式示例。实际账户应填本次核实的时间，当前数据、账户记录和确认请求使用一致的日期。

## 确认策略与持仓

```bash
"$PY" "$ROOT/quant-rebalance-kit/scripts/run.py" review \
  --config "$WORK/strategy.json" --account "$WORK/account.json" \
  --request "$WORK/request.json" --out "$WORK/review-01"
```

阅读`review.json`，向用户展示策略概要、完整持仓、可用现金和计划时间。收到用户回复后，在生成的`confirmation.json`中记录实际回复原文、确认时间，并将`confirmed`设为`true`。内容摘要由程序生成，不能自行替换。这个记录确认的是计算输入。

同一输入已有明确确认，可继续使用；更新策略、账户或请求后旧记录会失效。仅更新参考报价不改变策略与持仓确认，但应向用户展示新的报价时点。

## 准备数据与参考报价

用数据kit和策略kit的`prepare`补取信号所需历史行情、历史财务和已发布宏观指标。计划使用同一标准数据目录。日历至少覆盖预热区间、当前时点及下一次拟执行日，不能用周一至周五列表代替真实交易日历。

提前测算月底预案时，财务选股使用本次实际采用的信号日。如果已有财务截面只有上个季末，可通过数据kit的`extend.py stock-features --dates-file <日期数组JSON> --out <新目录>`补取该日截面，并按日期和代码并入工作数据副本。保留原始公告日，不把旧截面的日期改成今天。

另准备`instrument-rules.json`：每个需要估值或交易的证券给出`currency`、`buy_lot`、`sell_lot`。示例文件中的数值是格式演示，实际数值按对应证券和账户规则填写。外币证券实际计划需填写已核实的`execution_session`，例如当地市场可交易的拟执行日期。

```bash
"$PY" "$ROOT/quant-rebalance-kit/scripts/run.py" quotes \
  --data "$WORK/data" --rules "$WORK/instrument-rules.json" \
  --as-of '2025-06-30T16:00:00+08:00' --out "$WORK/quotes.json"
```

标准价格表已有`close_raw`、报价可用时间及美国证券原币行情时可直接提取。报价需覆盖当前持仓以及本次新入选的股票；计算提示缺少新入选代码时，补取对应行情和交易单位后重算。数据供应商没有这些原始字段时，使用数据模块补取，不能拿复权价代替。

## 计算并出报告

```bash
"$PY" "$ROOT/quant-rebalance-kit/scripts/run.py" plan \
  --config "$WORK/strategy.json" --data "$WORK/data" \
  --account "$WORK/account.json" --request "$WORK/request.json" \
  --quotes "$WORK/quotes.json" --confirmation "$WORK/review-01/confirmation.json" \
  --out "$WORK/plan-01"

"$PY" "$ROOT/quant-report-kit/scripts/run.py" rebalance \
  --plan "$WORK/plan-01" --out "$WORK/report-01"

"$PY" "$ROOT/quant-report-kit/scripts/run.py" check --report-dir "$WORK/report-01"
```

先看`plan.json`中的日期、状态与约束，再看报告：目标比例是策略计算结果，预计调整后比例已经考虑资金、交易单位和可卖数量，二者可能有差异。

`preliminary`表示信号日尚未到，需要在信号日更新；`constrained`表示存在无法完全达到目标的事项；`action=hold`表示该日未触发调仓。没有合适行情、资金或日历时，按提示补齐输入。计划生成不代表用户已执行，下一次以真实账户快照为准。

## 复现本项目历史验证

数据目录沿用上轮本地预演结果，不随kit打包。若该目录已被清理，用数据/策略kit重新获取相同区间的数据即可。

```bash
"$PY" "$ROOT/quant-rebalance-kit/scripts/run.py" demo \
  --config "$ROOT/output/策略数据交接_20261007/朋友示例_QDII_2025/strategy.json" \
  --data '/Users/ranli/Documents/Codex/temp/quant-teaching-corrections-20261007/friend-qdii/data' \
  --signal-date 2025-06-30 --out "$WORK/history-replay-01"

"$PY" "$ROOT/quant-report-kit/scripts/run.py" rebalance \
  --plan "$WORK/history-replay-01/plan" --out "$WORK/history-report-01"
```

演示从信号日之前的回测重建模拟金额，再按当时原始价换算模拟份额。使用很小的交易单位便于核对计算；实际计划应填写证券真实交易单位。核对目标权重与选股结果，不能要求信号日估算数量等于次日收盘模拟成交数量。
