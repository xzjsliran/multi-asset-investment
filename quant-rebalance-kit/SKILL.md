# 组合管理与调仓计划

用户询问“我现在应当怎么调仓”“按这套策略计算下月配置”“按当前持仓列买卖清单”时使用。Python计算目标和数量，宿主理解需求、确认输入及解释结果。依赖同级`quant-strategy-kit`，数据由`quant-data-kit`准备，客户呈现交给`quant-report-kit`。

## 使用前确认

实际使用先核对当前策略与实际持仓。读取用户已明确的策略文件、账户表及时间，汇总策略名称、资产配置、选股/配权、调仓频率、宏观条件、持仓数量、可卖数量、各币种现金、持仓时间、拟执行日期。只补问影响本次计算的缺项；资产部分归属不明需确认，尤其同一证券分属多个部分时。

对话中给出简洁确认说明，例如：“本次采用……策略，持仓截至……，可用现金……，计划在……调整，全部资产只做多。请确认这些策略和持仓信息是否准确，是否还有成交、未完成委托或资金变化。”用户已明确确认本次完整信息时可以沿用，不重复询问。

运行`review`生成摘要及未确认的记录模板；向用户展示摘要，收到实际回复后记录`confirmed=true`、确认时间及用户回复原文。不能把模板、示例回复或agent自己的总结当成用户确认。策略、持仓或请求变更后重新生成记录并确认变更；相同输入可复用已有确认。这个确认用于计算计划，不能据此提交委托。

用户明确要求演示时可采用既有策略与历史模拟账户，使用`mode=demo`并保留模拟标识；不向用户索要实际持仓。当前开发请求只授权演示，不替未来使用者确认其账户。

## 计算与交接

1. 阅读[使用指南](references/使用指南.md)和[输入输出约定](references/输入输出约定.md)，将实际输入保存到kit以外。持仓CSV可用`import-account`转换；保留代码前导零。空仓需要明确`initial_allocation=true`。
2. 数据截止时间必须带时区。使用数据kit补充复权研究行情、历史财务、已公布宏观指标及真实交易日历；未来交易日历缺失时补数，不能用普通工作日替代交易日。研究行情与买卖数量用的原始报价分别处理。
3. 交易单位和币种来自实际产品规则；`quotes`命令可从标准`prices.csv`提取原始报价及已知汇率。补齐现有持仓和新入选资产的报价。外币证券实际计划另提供已核实的`execution_session`，不能用中国日历推断海外可成交日。
4. `review` → 记录本次用户确认 → `plan`，具体命令见使用指南。发生输入变化时重做摘要；不能使用`demo`绕过实际账户确认。
5. 检查`plan.json`中的时间、事件、约束和目标差异。未来信号日尚未到时输出`preliminary`预案，到信号日再用已知数据重算。日历没有到期事件时维持持仓。计划中美元现金不足不能当成可用人民币自动换汇。
6. 把`handoff.json`交给报告kit，用其`rebalance`命令生成《组合调仓计划》，复核报告及数据。计划不能写成成交记录；用户执行后需更新真实持仓和现金，不能自动把推演结果当作实际账户。

## 计算要求

- 所有资产只做多：持仓、可卖数量、基础/动态/证券权重及目标持仓非负；现金不透支，卖出不超过已有可卖数量。负的收益、回撤或卖出差额不等于空头。
- 与历史回测共用`strategykit.decision.decide`；不另写一套实时选股或配权规则。大类调整保留未到内部调仓日的漂移比例；单独内部调整只使用该部分预算。
- 根据原始价、已知汇率、最小交易单位和现金计算数量；复权序列只用于研究信号。分币种检查资金，同一证券的不同部分交易在账户层合并净额。
- `state_if_fully_executed`是预期策略状态，不能当作执行回执。若宏观缺指标策略要求沿用上期配置，须提供上期配置状态。

套装仅包含代码、Schema、空模板和文档。行情、账户、凭证、确认记录和结果均保留在用户工作目录；本模块无需MCP或模型API。
