# 数据接口、输出与清理口径

这张表说明程序实际实现了什么。是否在某台电脑、某个日期还能连接，以运行后的 `manifest.json` 和 `quality.json` 为准。

## 行情和日历

| 数据 | 首选及备用 | 处理 |
| --- | --- | --- |
| 国内 ETF 日线 | AKShare `fund_etf_hist_em` → AKShare 新浪日线 + 新浪乘法因子 → 可选 Tushare `fund_daily` + `fund_adj` | 同一资产整段选同一来源；原始与后复权分开 |
| 境内QDII ETF日线 | 同上，例如513100.SH、513500.SH；配置kind仍为etf | 人民币场内价，中国日历，不重复换汇；已验证情况见QDII选择说明 |
| A 股日线 | AKShare `stock_zh_a_hist` → AKShare `stock_zh_a_daily` + 新浪因子 → 可选 Tushare `daily` + `adj_factor` | 同上，按年分段 |
| 国内交易日历 | AKShare `tool_trade_date_hist_sina` → 可选 Tushare `trade_cal` | 日历覆盖到完整周期，再算周/月/季末 |
| 代码映射 | 配置中的明确代码与证券类型 | 生成六位代码、交易所、腾讯代码、Tushare 代码和时区 |

示例清单包含 510300.SH、511010.SH、518880.SH，以及 159980.SZ、159981.SZ、159985.SZ。前三者作为股票、债券、黄金入口；后三者用于商品暴露实验。代码清单属于可修改配置，不是内置行情。

2026年10月7日新增扩展入口 `scripts/extend.py`：美国ETF及USD/CNY通过Yahoo Finance获取；历史估值、财务、行业、名称通过本地Tushare获取。策略模块的prepare会统一调用这些方法；基础 `run.py fetch` 的资产配置仍限境内ETF和A股。详细接口、字段和复现方法见 [海外行情与历史财务扩展](海外行情与历史财务扩展.md)。

`auto` 优先尝试免费源；某来源缺失较多时尝试备用源，最后整体采用覆盖最好的一条。如果没有完整来源，输出 `partial` 和缺失记录。不会在不同来源的复权绝对价之间直接拼接。

新浪 ETF 日线本身不带复权选项。本包另外获取新浪公开 `hfq.js` 因子，并按因子生效日期匹配；只有明确的纯乘法因子才参与计算。含累计现金项或份额转换项时换来源，不能直接把 `f=1` 理解为从未分红。四只黄金/商品候选 ETF 的因子为显式的单位因子，仍保存因子响应作为依据。

腾讯复权序列与 Tushare 的交叉核对发现部分标的日收益存在明显差别，已从自动取数链移出；`market_tx` 仅保留为参考方法，不作为课程默认研究来源。参考项目对口径的说明是排查起点，实际适用性仍通过数据核对确认。

东方财富成交量按手换算成份/股；Tushare 成交量按手、成交额按千元换算。新浪成交量保留来源原单位，不根据不同文档里的不一致描述猜测换算。原接口提供成交额时保留为元，不提供时不拿收盘价乘成交量伪造成交额。

接口参考：[AKShare 基金](https://akshare.akfamily.xyz/data/fund/fund_public.html)、[AKShare 股票](https://akshare.akfamily.xyz/data/stock/stock.html)、[AKShare 工具箱](https://akshare.akfamily.xyz/data/tool/tool.html)、[Tushare 接口目录](https://tushare.pro/document/2)。腾讯公开下载端点在 `providers.py` 中集中维护，属于网页公开数据的轻量获取方法，接口结构可能调整。

中国接口参考：[AKShare 宏观文档](https://akshare.akfamily.xyz/data/macro/macro.html)。其他来源：[FRED](https://fred.stlouisfed.org/)、[Cboe VIX](https://www.cboe.com/tradable-products/vix/vix-historical-data)、[世界银行 API 说明](https://datahelpdesk.worldbank.org/knowledgebase/articles/889392-about-the-indicators-api-documentation)。美国系列的具体含义见另一份指南。

## 宏观时间怎么处理

每条记录包含 `period`（统计期）、`release_at`（核实的发布时间）、`available_at`（本程序允许使用的时间）、`vintage`（版本）、来源和两个可用性标记。

中国 PMI/CPI 的普通历史接口没有完整公布时点。因此先下载数值；配置 `nbs_urls` 后，爬虫从国家统计局原公告解析月份、当期数值、公布时间。原公告值与今天的下载值可以同时存在。只读到日期而没有时间时，保守地从次日零点允许使用。

`nbs_crawl_pages` 可以指定从统计局“最新发布”目录读取几页，默认 0，避免为了短样本扫全站。按页抓到的文章仍需逐篇解析。较早年份用智能体搜索到的原公告 URL 更省时。

如果官网网络不通，可以在配置中加入：

```json
"nbs_saved_pages": [
  {"url": "https://www.stats.gov.cn/原公告地址.html", "file": "/你的工作目录/原公告.html"}
]
```

这里保存的是用户从官网另存的原始页面，不是 AI 重写的文章。

美国月度 CPI、失业率、非农的 FRED 普通下载属于当前修订历史，默认不直接进入历史信号。附带 `fred-vintage` 获取指定日期版本的方法，但完整历史回测仍需按决策日期取得各自快照并核对发布时间。

VIX、政策利率上限、美债收益率日数据使用“纽约次日零点可用”的教学假设。DFF 考虑次个美国营业日公布，第一版采用更保守的“四个自然日后纽约中午”假设。这些行允许进入示范对齐表，但 `pit_verified=false`，不能称作已经核实逐条发布时间。若策略对此敏感，应补官方发布日历后再缩短滞后。

`macro_asof.csv` 按国内每个交易日 16:00 找不晚于该时点的最新可用值。中国月度公告超过 62 天、VIX 超过 10 天、其他日频宏观超过 14 天时标记过期，不一直沿用。缺失前的值不向过去回填。

## 清理规则

1. 明确证券类型和交易所，保留六位代码前导零。
2. 统一日期、数值类型和排序；完全相同的重复记录去重并计数，重复日期但数值不一致时换源或报告。
3. 核对价格为正、数值有限、最高最低与开收盘关系正确、成交量和成交额非负。
4. 以交易所日历建立数据行。非交易日不列为缺失；未知缺失保留空值并记录。
5. 上市/退市日期只有在配置中提供可靠来源时才用于分类；否则只写“首个观察值以前、原因未核实”。
6. 不填充缺失价格；日收益只在相邻两个交易日都有有效复权价时计算。复权比例另存为派生字段，不冒充供应商原始因子。
7. 同一天国内收盘价按 16:00 后可用处理；周/月/季末信号对应的下一交易日另存。完整日历尚未覆盖的末端周期不冒充已确认周期末。

停牌、涨跌停、历史指数成分和财务公告另属后续数据扩展；本版没有根据“缺一行价格”自行推断停牌。

## 运行输出

- `request.json`：本次配置。
- `asset_mapping.csv`：标准代码和各来源代码。
- `prices.csv`：原始 OHLC、复权收盘、派生因子、相邻日收益、成交信息、质量标记。
- `calendar.csv`：日历、周/月/季末、下一交易日、是否在用户请求区间。
- `missing_and_invalid.csv`：有问题的资产日期。
- `macro_observations.csv`：宏观原始统计期与版本。
- `macro_asof.csv`：按国内决策时点对齐的可用记录。
- `quality.json` 和两份检查报告：覆盖和问题。
- `manifest.json`、`raw/`：接口参数、获取时间、依赖版本和本次原始响应快照，不含认证字段。

缓存按接口和参数区分，24 小时内复用；`--refresh` 重新获取。按年分段的成功请求可以在重跑时复用。网络错误少量重试，参数或权限问题不反复重试。每个请求还有独立子进程的时间上限，避免课堂无限等待。
