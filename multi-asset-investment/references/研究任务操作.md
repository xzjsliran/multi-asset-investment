# 资产配置研究任务操作

以研究工作目录作为当前目录。以下示例中的 `run.py` 指 Skill 的 `scripts/run.py`，使用已配置的 Python 解释器和实际路径。

## 保存需求

先按[策略模块说明](../quant-strategy-kit/SKILL.md)准备策略配置。确认资产和比例、起止日、配权、调仓层级、必要的基准或对照。任务单将策略配置另存一份，并记录文件指纹。回测沿用这份配置。

```json
{
  "objective": "比较固定比例和风险平价的持有风险",
  "metrics": ["max_drawdown", "annual_volatility"],
  "comparison": "standard",
  "specified": ["objective", "metrics", "sleeves", "start", "end", "allocation_rebalance"],
  "defaults": {"cost_rate": "按当前回测的零成本口径", "initial_capital": "沿用统一示例本金"}
}
```

`comparison` 为 `standard` 时，报告包含该策略实际导出的等权、固定权重或市场基准对照。`main_only` 只看主方案。两份独立回测用报告模块的 `build` 比较。指标支持 `total_return`、`annual_return`、`annual_volatility`、`max_drawdown` 和 `sharpe_zero_rf`。目标、指标或对照范围待确认时可先保存任务，返回的 `missing` 给出缺项。

```bash
python run.py research init --config strategy.json --request request.json --out task-quarterly
python run.py research show --task task-quarterly
```

## 预检与回测

标准数据目录应含 `calendar.csv` 和 `prices.csv`。可使用已有数据，也可通过 `strategy plan` 和 `strategy prepare` 准备。策略用到历史宏观或财务时一并检查相应文件。联网准备使用现有数据模块及备用源，同一证券采用一条完整来源。

```bash
python run.py research preview --task task-quarterly --data data
python run.py research run --task task-quarterly --data data --out run-quarterly
```

- `needs_input` 给出缺项或覆盖阻塞，先处理再运行。若给出建议起点，它表示固定证券已满足首次信号的历史价格要求。仍需按改后的区间重新预检共同样本。
- `ready_with_notes` 给出仍可按原配置运行的限制，例如已配置的风险平价回退。首次风险窗口列明已有、所需和缺少的共同观测数。
- `run` 在计算前重新预检。运行成功后保存 `coverage.json`、`run.json` 和 `backtest/`。`execution_review` 列出回退次数、原因、日期和缺少的对照。全程回退时报告先披露实际执行规则。
- 使用 `report_args` 作为 `python run.py report` 的参数，可沿用任务单的报告指标与对照。命令参数中的路径用引号保护。输出目录每次使用新名字。
- 若需要 AI 解读，先生成基础报告。随后按 `ai_context.json` 的 `evidence_values` 生成 `claims`，引用对应的 `fact_id`，在新的报告目录生成带解读的版本。数字由程序填入，正文保留定性分析。详见[报告模块说明](../quant-report-kit/SKILL.md)。

## 单项修订

只改大类调仓频率时，在 `changes.json` 中填写 `{"allocation_rebalance":"monthly"}`。若用户明确指某个资产部分的内部频率，用 `{"sleeve_rebalance":{"equity":"monthly"}}`。起止日可用 `start`、`end` 修改。补齐目标、指标或对照可用 `request` 对象。

```bash
python run.py research revise --task task-quarterly --changes changes.json --out task-monthly
python run.py research preview --task task-monthly --data data
```

核对返回的 `change.strategy_fields`。区间或频率变化可能带来新的数据要求。资产或权重变化时，以修改后的策略配置建立新任务。原任务、配置和结果用于复核。

已有调仓计划与报告导入继续使用原模块命令。

## 在新会话中接续研究

每个研究目录的一份 `research-task.json` 保存该研究的历次版本。每版记录引用的任务单、实际比较的方案、数据目录和文件指纹、已保存的回测与报告，以及当前步骤和待解决问题。完整策略和研究需求见各版引用的 `strategy.json` 和 `task.json`。新回测和报告存入 `research-versions/`，每版使用独立子目录。

新研究登记已确认的任务，已有数据时附上目录。多个独立方案重复传 `--task`，默认比较各自的主方案。

```bash
python run.py research track --task task-quarterly --data data
python run.py research continue
```

接入 0.4 时，`resume` 会列出当前目录的直接子目录中已完成的旧回测。一份可用的旧回测可由 `continue` 直接接入。对于多个独立方案，按上次报告的比较范围登记。如果曾生成自定义报告，提供含 `report_config.json` 和 `manifest.json` 的报告目录以沿用方案标签、顺序、指标和比较区间。

```bash
python run.py research track --run run-fixed --run run-risk-parity --comparison old-report
```

第二天打开同一个研究目录，先查看当前状态，再按用户改动生成新结果。也可以给这三条研究命令附 `--workspace "/路径/原研究目录"`。

```bash
python run.py research resume
python run.py research continue --changes changes.json
```

- 若只改大类调仓频率，变更文件使用 `{"allocation_rebalance":"monthly"}`。独立方案逐一更新，同一回测的固定权重对照随主方案重新计算。市场基准若入选，仍按买入持有处理。
- 复用须通过两层检查。先逐个核对标准数据文件的原指纹，再用新日期和调仓日历预检覆盖、历史窗口和当时可用的财务截面。缺项按 `issue` 处理，恢复原数据后运行 `research continue`。若确认换用新快照，可使用 `research continue --data "/路径/标准数据目录"`，供本版各方案共同使用。
- 研究进度从任务保存、回测完成到报告完成逐项登记。中断后运行 `research continue` 续做，已完成并保存的步骤可复用。若要更换研究设定，传新的变更文件。独立的研究问题用另一个工作目录。
