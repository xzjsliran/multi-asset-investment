# 策略与回测组交给报告组什么

输入、规则和记账由前两组完成。报告组接收一个结果目录，读取数值、设计图表、解释策略表现，并选择网页、文档或其他展示方式。

## 先读清单

入口为 `handoff.json`，`schema_version=1`。包含策略名称、区间、币种、本金、单位、计算口径、实际存在的方案及文件列表。CSV采用UTF-8 BOM编码，日期为YYYY-MM-DD；无记录的表仍有表头。JSON缺失值为null，CSV为空单元格，不写成0收益。

收益率、权重、波动和回撤都是小数：0.12显示成12%；金额为人民币元；净值初始为1。回撤保存负数，例如-0.08表示回撤8%。ROE等原始选股指标保留数据模块单位，不能将所有字段一律乘100。

本产品全部资产只做多。交接中的`conventions.position_policy=long_only`，持仓及目标权重非负，现金不透支；报告应核对实际明细。负收益、回撤和卖出金额正常保留。新导出的`final_state.json`包含期末模拟持仓及策略状态，数量以复权记账单位表示，不能直接当作实际账户份额。当前调仓使用相邻`quant-rebalance-kit`确认用户真实账户后计算。

## 文件及主要字段

| 文件 | 内容与字段 | 报告组怎样使用 |
| --- | --- | --- |
| daily.csv | date、nav、equity、return、cash_weight、drawdown、pnl_各部分 | 当前策略净值、回撤与每日盈亏 |
| curves.csv | date及strategy/equal_weight/static/benchmark中实际存在的列 | 各方案净值已对齐，可直接绘图 |
| summary.json | 起止、总收益、年化收益、波动、最大回撤、零无风险夏普、期末资金、交易日数 | 当前策略指标 |
| comparison.json | scenario、label及与summary相同的指标 | 同口径方案比较 |
| annual.csv | year、return | 当前策略逐年收益 |
| weights.csv | date、sleeve、code、value、weight | 每天收盘调仓后的实际持仓，比例相对全组合 |
| trades.csv | date、signal_date、sleeve、code、amount、side、cost | 实际成交；amount买入为正、卖出为负 |
| targets.csv | execution_date、signal_date、sleeve、code、target_value、portfolio_weight | 各次调仓目标；目标与实际成交可能有差别 |
| selections.csv | signal_date、execution_date、sleeve、code、name、within_weight，以及相应方法的筛选字段 | 本期入选名单与内部比例；内部比例相对所属部分 |
| contributions.json | 各sleeve的累计盈亏 | 资产部分贡献，金额合计等于总盈亏 |
| regimes.json | 各次配置检查的状态、条件数据及权重 | 动态配置发生时间及依据 |
| optimization.json | 各次配权状态、样本量、约束或回退原因 | 最小方差求解与等权回退记录 |
| blocked.csv | date、sleeve、code、side、reason、amount | 暂未执行的交易尝试，不能计作已成交 |
| valuation_gaps.csv | date、sleeve、code、missing_sessions、mark_price、action | 长期缺报价的持仓估值记录 |
| unfilled_at_end.json | 结束时仍有待成交目标的部分ID | 未完成交易状态 |
| assets.json | sleeves名称、基础比例，以及configured_assets | 图例与名称；选股当时名称可从selections取 |
| strategy.json | 完整配置 | 本次具体策略和参数 |
| checks.json | 权重和、盈亏复算误差、时序错误数及缺口计数 | 结果是否可复算、哪些情况需解释 |
| manifest.json | 输入来源、价格摘要、计算说明、省略的比较方案 | 可追溯性及说明文字的依据 |

`daily.csv` 的 `pnl_` 列随资产部分变化；`selections.csv` 的附加字段随选择方法变化。程序保证共同字段，报告组按清单中的实际列读取。`CASH`是实际持仓表的现金代码；目标表中现金代码为`__cash__`。`sleeve=cash`表示未分配给具体部分的现金，其余部分也可以留有现金。

## 对照方案

- strategy：用户配置的主方案，必有。
- equal_weight：仅将最小方差部分改成等权；配置存在最小方差且启用对照时生成。
- static：保留动态配置的相同调仓日期，把各状态权重统一改回基础比例；只有宏观策略时生成。
- benchmark：配置的基准从首个执行日收盘买入持有；行情未完整覆盖时省略，原因写入manifest及handoff。

各对照的完整日数据分别在 `equal_weight_daily.csv`、`static_daily.csv`、`benchmark_daily.csv`。这些文件和净值列按实际存在的方案导出，报告组从handoff读取，避免假定所有运行都有四条曲线。

## 数值口径

当日先按旧持仓计收益，再在收盘调仓；信号来自此前交易日。没有调仓时持有份额不变。零成本、现金零收益、允许分数份额。

总收益为期末净值减1，年度收益是该年每日收益连乘。年化收益按首末日之间的日历年长度折算，波动用样本标准差乘√252，夏普以零无风险利率计算。完整区间报告可以核对这些已算指标。相邻的 `quant-report-kit` 比较不同结果时，以各自共同首日净值为1，按同样公式重算共同区间，并另列原完整区间；需要改变策略或记账规则时再由策略组修改并重跑。

跨境直接ETF使用已知报价及汇率折人民币；境内QDII使用自己的人民币场内价格。实际折溢价、市场日历和产品差异会体现在结果里。

最近一次历史目标只表示回测中那次决策。将来制作“本月末怎么调”的功能，需要用最新数据和当前持仓调用同一套决策逻辑，再导出新的目标数据。

## 交接时做一个小检查

报告组无需调用回测引擎，读取文件即可核对：期末净值乘初始本金等于期末资金；最后一天各持仓value合计等于期末资金；各部分contributions合计等于期末资金减本金；年度收益连乘能还原期末净值。当前导出测试已覆盖这些关系。
